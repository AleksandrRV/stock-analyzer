# 03. Архитектура

Проект построен на принципах **Clean Architecture (Чистой архитектуры)** и **модульного монолита**.

Главный принцип — **полная независимость бизнес-логики и математики от UI-фреймворка и источников данных**. Можно заменить React на Vue, а Мосбиржу на Yahoo Finance, не переписывая математику расчётов.

## Принципы

1. **Слоистость.** Приложение разделено на 4 слоя; зависимости направлены строго извне внутрь. Внутренний слой (математика) ничего не знает о UI и API.
2. **Модульность.** Каждая доменная область (расчёт сложного процента, интеграция с MOEX, импорт/экспорт) вынесена в изолированный модуль со своим интерфейсом.
3. **Чистая доменная логика (Pure Domain).** Вся математика портфеля — чистый TypeScript без зависимостей от React, DOM и браузерных API. Её можно тестировать изолированно.
4. **Паттерн Репозиторий.** Бизнес-логика не знает, откуда берутся цены — из IndexedDB, JSON-файла или с сервера Мосбиржи. Она запрашивает данные через универсальный интерфейс.

## Схема слоёв

```
┌────────────────────────────────────────────────────────┐
│               PRESENTATION LAYER (UI)                  │
│       (React-компоненты, Tailwind, Recharts)           │
└───────────────────────────┬────────────────────────────┘
                            │ (вызывает действия / читает стейт)
┌───────────────────────────▼────────────────────────────┐
│          APPLICATION LAYER (State & Orchestration)      │
│         (Zustand Store, сервисы оркестрации)           │
└───────────────────────────┬────────────────────────────┘
                            │ (использует для расчётов и правил)
┌───────────────────────────▼────────────────────────────┐
│                 DOMAIN LAYER (Core Engine)             │
│   (калькуляторы, хронология, резолвер тикеров, время)  │
└───────────────────────────▲────────────────────────────┘
                            │ (поставляет данные через интерфейсы)
┌───────────────────────────┴────────────────────────────┐
│            INFRASTRUCTURE LAYER (Data & I/O)           │
│     (MOEX Gateway, IndexedDB, localStorage, файлы)     │
└────────────────────────────────────────────────────────┘
```

## Разбор слоёв и модулей

### DOMAIN LAYER — ядро и бизнес-логика
«Мозг» приложения: чистые функции и изолированные математические модули.

| Модуль (файл в `src/engine/`) | Ответственность |
|---|---|
| `FinancialMath` | Геометрическая доходность (сложный процент), среднемесячная/среднегодовая доходность, Альфа (превышение над MCFTR), вычет налога с дивидендов |
| `TimelineEngine` | Склейка контрольных точек в единую временную цепь, длительность точек (с точностью до часа), автозаполнение остатка кэша активом LQDT, определение даты завершения |
| `TickerResolver` | «Машина времени тикеров»: подстановка актуального тикера с учётом даты точки (например, `TCSG` для 2022 года и `T` для 2024-го) |
| `DateTimeStandardizer` | Конвертация времени: часовой пояс пользователя ↔ UTC (хранение) ↔ MSK (запросы к MOEX) |
| `CalendarAdjuster` | Поиск ближайшего торгового дня «назад», если точка или стык месяцев выпадает на выходной/праздник |
| `NumberFormatter`, `TickerSearch` | Форматирование чисел и поиск/подсказки тикеров |

### INFRASTRUCTURE LAYER — данные и ввод-вывод
Внешние коммуникации: сеть, база данных, файловая система.

| Модуль (файл в `src/`) | Ответственность |
|---|---|
| `services/api/MoexApiGateway` | Прямые HTTP-запросы к `iss.moex.com`: цены акций/фондов, индексы, дивиденды. Обрабатывает сетевые ошибки и таймауты |
| `services/api/SmartLabGateway` | Резервный источник истории дивидендов (парсинг SmartLab) через CORS-прокси |
| `db/marketDb` | Рыночный кэш на IndexedDB (Dexie.js): таблицы цен, дивидендов и метаданных кэша, гранулярная очистка |
| `services/storage/userStorage` | Хранение структуры портфелей, групп и настроек в localStorage |
| `services/storage/filePortability` | Экспорт/импорт состояния в JSON, валидация; адаптер File System Access API с фоллбэком на скачивание через Blob |

### APPLICATION LAYER — оркестрация и состояние

| Модуль | Ответственность |
|---|---|
| `store/usePortfolioStore` | Управление портфелями и группами (CRUD), настройками, кэшем расчётов; сохранение в `UserStorage` |
| `services/sync/MarketDataSyncService` | Паттерн Read-Through Cache: сначала кэш → при промахе MOEX → запись в кэш |
| Ленивая загрузка групп | Загрузка цен только для активной группы портфелей; данные других групп — по факту открытия вкладки |
| `hooks/usePortfolioCalculation`, `useMilestoneMarketData` | Реактивная связка UI с расчётным движком и проверкой активов |

### PRESENTATION LAYER — пользовательский интерфейс

| Компонент | Назначение |
|---|---|
| `Header`, `App` | Каркас приложения, шапка, переключатель тем, статус сети, навигация |
| `DashboardView`, `PortfolioCard` | Список портфелей активной группы, табы групп, карточки с цветовой индикацией Альфы |
| `PortfolioDetailView` + `components/milestones/*` | Редактор контрольных точек, добавление активов, контроль свободного кэша, ребалансировка |
| `components/analytics/*` | Графики доходности (Recharts), матрица доходности по месяцам |
| `SettingsView` | Глобальные настройки, экспорт/импорт JSON, гранулярная очистка кэша |
| `components/common/*` | ErrorBoundary, PWA-подсказка об установке |

## Пример потока данных: добавление контрольной точки

1. **UI.** Пользователь выбирает дату и час (локальное время), вводит тикер и нажимает «Сохранить» → вызов метода в `PortfolioStore`.
2. **`PortfolioStore`.** Переводит дату в UTC (`DateTimeStandardizer`), сохраняет точку (`UserStorage`), запрашивает синхронизацию котировок.
3. **`MarketDataSyncService`.** Через `TickerResolver` определяет актуальный тикер для даты; проверяет цену в IndexedDB; при отсутствии запрашивает у `MoexApiGateway` (если биржа закрыта — `CalendarAdjuster` сдвигает дату к последней сессии); записывает свежую цену в кэш.
4. **Domain.** `FinancialMath` и `TimelineEngine` пересчитывают общую доходность, доходность LQDT для остатка кэша и Альфу относительно MCFTR.
5. **UI.** `DashboardView` и `AnalyticsView` получают обновлённые данные и перерисовывают карточку портфеля и график.

## Преимущества архитектуры

- **Тестируемость.** Математику ядра можно полностью покрыть unit-тестами без браузера и DOM.
- **Заменяемость источников данных.** Смена API биржи затрагивает только `MoexApiGateway` — математика, хранилища и UI не замечают изменений.
- **Заменяемость хранилищ.** Смена Dexie.js на другую БД меняет только класс в слое Infrastructure.
- **Безопасный рефакторинг.** Разработчик UI графиков физически не может сломать логику сложного процента или налога на дивиденды.
