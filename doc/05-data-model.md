# 05. Модель данных и хранение

Приложение использует **строгое физическое разделение хранилищ**: пользовательские данные (стратегии) и тяжёлый рыночный кэш лежат в разных местах, чтобы очистка кэша никогда не удаляла портфели пользователя.

## Два хранилища

### 1. Пользовательские данные — `localStorage`
Лёгкие данные, формирующие JSON-файл при экспорте.

| Ключ localStorage | Содержимое |
|---|---|
| `app_global_settings` | Глобальные настройки (ставка налога, переименования тикеров, сплиты) |
| `app_user_portfolios` | Массив портфелей |
| `app_user_groups` | Массив групп (папок) |

### 2. Рыночный кэш — IndexedDB (Dexie.js, БД `MarketCacheDB`)
Тяжёлые исторические данные (котировки за годы).

| Таблица | Содержимое | Первичный ключ |
|---|---|---|
| `prices` | Цены акций, фондов и индексов (`type`: `STOCK`/`FUND`/`INDEX`) | `[ticker+date]` |
| `dividends` | История дивидендов (включая ручные записи `isManual`) | `[ticker+date]` |
| `meta` | Метаданные кэша: время последнего обновления (`lastUpdatedMs`) для TTL | `key` |

Составной ключ `[ticker+date]` гарантирует отсутствие дубликатов даже при сбоях сети и повторных запросах.

## Доменные типы (`src/types/domain.ts`)

| Тип | Поля | Назначение |
|---|---|---|
| `IPortfolio` | `id`, `groupId`, `name`, `createdAt`, `closedAt`, `milestones[]` | Портфель (стратегия) |
| `IMilestone` | `id`, `date` (ISO UTC), `assets[]` | Контрольная точка — исторический срез состава |
| `IAssetAllocation` | `ticker`, `weight` (%), `type` (`STOCK`/`FUND`) | Актив и его доля в точке |
| `IPortfolioGroup` | `id`, `name`, `isArchive?` | Группа (папка) портфелей |
| `IGlobalSettings` | `dividendTaxRate` (по умолчанию 15), `tickerRenames[]`, `stockSplits[]` | Глобальные настройки |
| `ITickerRename` | `oldTicker`, `newTicker`, `changeDate` | Правило переименования тикера |
| `IStockSplit` | `ticker`, `date`, `coefficient` | Правило сплита/дробления |
| `IPriceHistory` | `ticker`, `date`, `price`, `type?` | Запись цены в кэше |
| `IDividendHistory` | `ticker`, `date`, `value`, `isManual?` | Запись дивиденда |
| `IExportData` | `schemaVersion`, `exportedAt`, `settings`, `groups`, `portfolios` | Формат файла экспорта |

## Группы (папки)

- Портфели распределяются по группам через поле `groupId` (или `null` — «без группы»).
- Существуют системные группы: **«Базовая»** (по умолчанию) и **«Архив»**.
- Удаление группы переводит входящие в неё портфели в «без группы», но не удаляет их.

## Контрольные точки (Milestones)

- Портфель — это **хронологический массив контрольных точек**, отсортированный по дате.
- Точка задаётся с точностью до **часа** (минуты и секунды отбрасываются).
- В точке перечислены активы (акции и/или фонды) с долями в процентах. Сумма долей ≤ 100%; остаток — «свободный кэш» (см. `06-business-logic.md`).

## Экспорт / импорт

- **Экспорт** сохраняет настройки, группы и портфели в единый версионированный `.json` (по умолчанию `moex_strategies_backup.json`, `schemaVersion: 1`).
- **Импорт** полностью восстанавливает среду и жёстко валидирует файл: корректный JSON, `schemaVersion === 1`, наличие `portfolios`, целостность точек и активов, сумма долей активов в точке ≤ 100%.
- На десктопе (Chrome/Edge) используется File System Access API для «тихой» перезаписи файла; иначе — классическое скачивание через Blob.

## Управление рыночным кэшем

Гранулярная очистка (не затрагивает портфели):
1. только цены акций;
2. только цены фондов;
3. только значения индексов (MCFTR);
4. только историю дивидендов;
5. полная очистка рыночного кэша.

После любой очистки сбрасывается и кэш расчётов, чтобы карточки/графики пересчитались по свежим данным.
