# 09. Известные ограничения и бэклог

Документ фиксирует результаты аудита кодовой базы: подтверждённые проектные решения и список незакрытых задач. Он предназначен разработчикам, планирующим следующие итерации.

## Подтверждённые проектные решения (не являются багами)

1. **Пересчёт графика на каждый клик по таймфрейму — намеренно.** Любой отрезок должен строиться от 0% (см. `07-performance.md`), поэтому кривая не кэшируется и не «обрезается».
2. **Границы месяцев в UTC-полдень (12:00 UTC).** Исключает сдвиг на следующий день при переводе в MSK; месячные точки матрицы считаются как «цена закрытия прошлого месяца → цена закрытия этого месяца».
3. **Ручной ввод дивидендов с авто-сверкой ±30 дней** — осознанная защита от задержек раскрытия данных MOEX.

## Уже исправлено по итогам аудита

- Сдвиг «конца месяца» на MSK (был 23:00 UTC → следующий день).
- Предзаполнение полей `datetime-local` UTC-временем вместо локального.
- `mcftrTotalProfitPercent` всегда возвращал 0.
- Тройное дублирование расчётного блока (~40 строк) — вынесено в общий метод.
- Последовательные `await` по активам — заменены на `Promise.all`.
- Матрица пересчитывалась при каждом монтировании — добавлен `matrixCache`.
- `DashboardView` перечитывал localStorage при каждом монтировании — перенесено в `App.tsx` (один раз при старте).
- Пробел в URL запроса MOEX — экранирован (`%20`).
- Импорт бэкапа не валидировался — добавлена проверка структуры и суммы весов ≤ 100%.
- Настройки читались из localStorage в каждом расчётном методе — теперь передаются параметром.
- Очистка рыночного кэша не сбрасывала кэш расчётов — теперь вызывает `clearCalculationCache()`.
- Гранулярная очистка цен акций/фондов не различала типы — в схему `prices` (v3) добавлено поле `type`, очистка фильтрует по нему.

## Открытый бэклог

1. **Матрица доходности: ключ часового кэша без даты.** В `MonthlyReturnsMatrix` валидность кэша проверяется по `new Date().getHours()` (число 0–23 без даты). Если приложение не перезагружается больше суток, в тот же час следующего дня кэш ошибочно считается свежим. Для расчёта портфеля это уже исправлено (используется абсолютный часовой таймстемп `Math.floor(Date.now() / 3_600_000)`); то же нужно сделать для матрицы.

2. **Подсказка о переименовании тикера игнорирует пользовательские правила.** В списке активов точки `TickerResolver.resolveTicker` вызывается без `customRenames` из настроек — страдает только визуальная подсказка `(TCSG → T)`; сам расчёт использует корректный список. Косметический дефект.

3. **Внешние циклы расчётов всё ещё последовательны.** Параллелизм (`Promise.all`) сделан «вглубь» (активы внутри суб-периода), но не «вширь»: `calculatePortfolio` и `calculateMonthlyReturnsMatrix` обходят контрольные точки/месяцы последовательно с `await` в цикле. Каждая точка/месяц независима — их можно запускать параллельно с агрегацией в конце. Для кривой графика (накопительный процент) полная параллелизация невозможна, но можно разделить два этапа: параллельно получить «сырые» доходности суб-периодов, затем синхронно свернуть их в накопительную кривую.

4. **Точечная загрузка цен вместо диапазона свечей.** `MarketDataSyncService`/`MoexApiGateway` запрашивают цену «по одной дате» на тикер, а не весь диапазон дневных свечей одним запросом с записью пачкой (`bulkPut`) в IndexedDB. Для прогретого кэша это незаметно, но на первой загрузке нового портфеля остаётся главным источником задержки.

## Ограничения продукта (осознанные)

- **Сплиты акций.** Встроенный справочник покрывает популярные случаи; остальные — на ручном контроле пользователя (можно добавить правило в настройках).
- **Фонды учитываются без дивидендов** (только изменение цены).
- **График строится только по контрольным точкам** — внутридневные/ежедневные колебания между точками не отображаются (снижение сетевой нагрузки).
