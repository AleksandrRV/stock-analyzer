# Мастер-документ проекта: Платформа анализа фондовых стратегий

## 1. Фундаментальная концепция и Архитектура
* **Тип приложения:** Progressive Web App (PWA), Serverless (чистый фронтенд).
* **Zero-Install & Offline-First:** Приложение работает в браузере, устанавливается на устройства (Android/iOS/Windows/macOS) в один клик и полностью функционирует без подключения к интернету за счет кэширования статики (Workbox) и данных (IndexedDB).
* **Приватность:** Нулевая передача пользовательских данных на внешние серверы. Все портфели живут только на устройстве пользователя.
* **Технологический стек:** 
  * Ядро: React 18/19, TypeScript (Strict Mode), Vite.
  * Управление состоянием: Zustand (UI-стейт), TanStack Query (оркестрация API).
  * Базы данных: Dexie.js (IndexedDB для рыночного кэша).
  * UI/Визуализация: Tailwind CSS, shadcn/ui, Recharts.

## 2. Модель данных и Локальное хранилище
Приложение использует **строгое физическое разделение баз данных** для защиты пользовательских стратегий от потери при очистке кэша.

### 2.1. База пользовательских данных (User Data)
Хранит настройки и структуру портфелей. Формирует JSON-файл при экспорте.
* **Глобальные настройки:** Единые правила для всего приложения (например, ставка налога на дивиденды — по умолчанию 15%).
* **Справочник тикеров (Corporate Actions):** Встроенная и пополняемая пользователем база переименований тикеров (TCSG -> T, YNDX -> YDEX) с датами изменений для корректных запросов к API в историческом контексте.
* **Группы (Папки):** Система тегирования/группировки портфелей. Существует системная "Базовая группа" (по умолчанию) и "Архив".
* **Структура портфеля:** Портфель состоит из метаданных (Название, Дата создания, Дата закрытия) и хронологического массива "Контрольных точек" (Milestones).

### 2.2. База рыночных данных (Market Cache)
Хранит тяжелые исторические данные в IndexedDB.
* **Кэш цен и дивидендов:** Отдельные таблицы для цен акций, цен фондов, значений индексов и истории дивидендов.
* **Управление кэшем:** Возможность гранулярной очистки кэша без затрагивания портфелей. Варианты очистки: 
  1. Только акции; 
  2. Только фонды; 
  3. Только индексы; 
  4. Только дивиденды; 
  5. Полная очистка рыночного кэша.

## 3. Бизнес-логика портфелей и Контрольных точек
* **Удаление портфелей:** Строго поштучно с окном подтверждения. Массовое удаление запрещено для защиты от случайных действий.
* **Контрольные точки (Milestones):**
  * **Точность:** Задаются с точностью до **часа** (минуты и секунды отбрасываются).
  * **Жизненный цикл:** Точка действует до наступления следующей по хронологии точки, либо до "Даты закрытия" портфеля. Если портфель открыт и будущих точек нет — точка действует "до текущего момента", а её доходность пересчитывается каждый новый час.
* **Состав точки:** Включает тикеры акций и/или фондов с указанием их долей (весов) в процентах. Фонды учитываются только по изменению цены (без дивидендов).
* **Свободный кэш (LQDT):** Если сумма долей выбранных активов меньше 100%, нераспределенный остаток ("Свободный кэш") **автоматически** генерирует доходность по историческим котировкам фонда денежного рынка (LQDT).

## 4. Финансовая математика и Обработка краевых кейсов
* **Сложный процент (Compound Interest):** Абсолютно все расчеты среднемесячных или среднегодовых доходностей осуществляются строго по формулам сложного процента (геометрическая доходность). *Пример: 1% мес = 12.68% годовых.*
* **Обработка неторговых дней:** Если контрольная точка или конец месяца выпадает на выходной/праздник, алгоритм автоматически берет последнюю доступную цену закрытия предшествующей торговой сессии.
* **Приостановка торгов / Делистинг:** В случае отсутствия торгов по активу в нужную дату, алгоритм использует последнюю известную историческую цену актива и тянет её вперед.
* **Обработка дивидендов:** Дивиденды учитываются по дате отсечки. Сумма дивиденда, очищенная от глобального налога (по умолчанию 15%), напрямую прибавляется к цене акции в этот день для расчета профита. Сплиты акций игнорируются (остаются на ручном контроле пользователя).

## 5. Интеграция с API Московской Биржи (MOEX)
* **Прямые запросы (No Proxy):** Приложение обращается к `iss.moex.com` напрямую через браузерный `fetch` (CORS разрешен).
* **Ленивая загрузка (Lazy Loading):** При старте приложения сетевые запросы и расчеты запускаются **только** для портфелей из "Базовой группы". Данные архивных или других групп загружаются исключительно при переходе пользователя в соответствующую вкладку.
* **Часовые пояса (Timezones) — Критическое правило:** 
  1. Пользователь видит и вводит даты в своём **локальном** часовом поясе.
  2. В базе данных все временные метки хранятся строго в **UTC**.
  3. Запросы к API Мосбиржи формируются в Московском времени (MSK) или UTC (согласно спецификации конкретного эндпоинта).

## 6. Визуализация, Метрики и UI/UX
* **Ключевая метрика (Альфа):** Главный показатель эффективности портфеля — разница (в %) между среднемесячной доходностью портфеля и среднемесячной доходностью индекса MCFTR (Индекс Мосбиржи полной доходности) за строго идентичный период.
* **Цветовая индикация (Дашборд):**
  * *Слегка красный:* Превышения над MCFTR нет (Альфа <= 0).
  * *Слегка желтый:* Превышение составляет от 0.01% до 0.9%.
  * *Слегка зеленый:* Превышение более 0.9%.
* **График доходности (Equity Curve):**
  * Линейный график, отображающий рост портфеля и бенчмарка (MCFTR).
  * Строится **строго по узлам (контрольным точкам)** и завершается на "Дате закрытия" или текущем дне. Промежуточные ежедневные колебания между точками не загружаются и не отрисовываются (снижение сетевой нагрузки).
  * Доступные фильтры периодов: 1М, 3М, 6М, 1 Год, YTD (С начала года), Всё время.
* **Матрица доходности (Monthly Returns Table):** 
  * Сводная таблица финансового результата строго по календарным месяцам. 
  * Для расчета запрашиваются промежуточные цены на стыке месяцев. 
  * Доходности за неполные месяцы (в начале и конце срока жизни портфеля) отображаются, но визуально помечаются как неполные.
* **Адаптивность:** Полноценная поддержка мобильных устройств (карточки, тач-интерфейс) и десктопов (многоколоночные Data Grids для таблиц).

## 7. Портативность данных (Data Portability)
* **Экспорт:** Кнопка скачивания всех пользовательских данных (портфелей, настроек, групп) в единый версионированный `.json` файл (через Blob API).
* **Импорт:** Загрузка `.json` файла для полного восстановления среды.
* **Seamless Save (Desktop):** Использование File System Access API в браузерах с его поддержкой (Chrome/Edge на ПК) для тихой перезаписи открытого файла стратегии без генерации дублей скачанных файлов.
