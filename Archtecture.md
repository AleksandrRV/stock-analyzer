Вот детально проработанная архитектура приложения, построенная на принципах **Clean Architecture (Чистой архитектуры)** и **модульного монолита**. 

Главный принцип этой архитектуры — **полная независимость бизнес-логики и математики от UI-фреймворка и от конкретных источников данных**. Вы сможете легко заменить React на Vue, а Мосбиржу на Yahoo Finance, не переписывая математику расчетов.

***

# Архитектурный документ: Анализатор фондовых стратегий

## 1. Архитектурные принципы
1. **Слоистость (Layered Architecture):** Приложение разделено на 4 четких слоя. Зависимости направлены строго извне вовнутрь. Внутренний слой (Математика) ничего не знает о внешних слоях (UI или API).
2. **Модульность:** Каждая доменная область (например, Расчет сложного процента, Интеграция с MOEX, Импорт/Экспорт) вынесена в изолированный модуль со своим интерфейсом (API модуля).
3. **Независимость бизнес-логики (Pure Domain):** Вся математика портфеля написана на чистом TypeScript. В ней нет зависимостей от React, HTML, DOM или браузерных API. Её можно тестировать изолированно (Unit-тестами).
4. **Паттерн Репозиторий (Repository Pattern):** Слой бизнес-логики не знает, откуда берутся цены — из базы Dexie.js, из JSON-файла или с сервера Мосбиржи. Он запрашивает данные через универсальный интерфейс `MarketDataRepository`.

---

## 2. Общая схема слоев

```
┌────────────────────────────────────────────────────────┐
│               PRESENTATION LAYER (UI)                  │
│       (React Components, Tailwind, Recharts, Views)    │
└───────────────────────────┬────────────────────────────┘
                            │ (вызывает действия / читает стейт)
┌───────────────────────────▼────────────────────────────┐
│          APPLICATION LAYER (State & Orchestration)      │
│         (Zustand Stores, TanStack Query, Services)     │
└───────────────────────────┬────────────────────────────┘
                            │ (использует для расчетов и бизнес-правил)
┌───────────────────────────▼────────────────────────────┐
│                 DOMAIN LAYER (Core Engine)             │
│   (Calculators, Timezone Engine, Ticker Resolver, Math)│
└───────────────────────────▲────────────────────────────┘
                            │ (поставляет данные через интерфейсы)
┌───────────────────────────┴────────────────────────────┘
│            INFRASTRUCTURE LAYER (Data & I/O)           │
│     (MOEX Gateway, Dexie DB, File System, Storage)     │
└────────────────────────────────────────────────────────┘
```

## 3. Подробный разбор слоев и модулей

### 3.1. DOMAIN LAYER (Слой ядра и бизнес-логики)
*Это "мозг" приложения. Состоит из чистых функций и изолированных математических модулей.*

* **Модуль `FinancialMath` (Финансовый калькулятор):**
  * *Ответственность:* Вычисление геометрической доходности (сложный процент), расчет среднегодовой и среднемесячной доходности, вычисление Альфы (превышения над MCFTR), дисконтирование налогов на дивиденды.
* **Модуль `TimelineEngine` (Управление хронологией):**
  * *Ответственность:* Склеивание контрольных точек в единую временную цепь, определение длительности точек (с точностью до часа), автозаполнение нераспределенного остатка долей активом LQDT, определение даты завершения (Дата закрытия или текущий час).
* **Модуль `TickerResolver` (Машина времени тикеров):**
  * *Ответственность:* Преобразование тикеров с учетом даты контрольной точки (например, возврат `TCSG` для 2022 года и `T` для 2024 года на основе глобальной карты переименований).
* **Модуль `DateTimeStandardizer` (Стандартизация времени):**
  * *Ответственность:* Конвертация времени между тремя стандартами: Часовой пояс пользователя (UI) $\leftrightarrow$ UTC (Хранение в БД) $\leftrightarrow$ Московское время MSK (Запросы к MOEX).
* **Модуль `CalendarAdjuster` (Корректор торговых дней):**
  * *Ответственность:* Логика поиска ближайшего доступного торгового дня "назад", если контрольная точка или стык месяцев выпадает на выходной/праздник или период приостановки торгов.

---

### 3.2. INFRASTRUCTURE LAYER (Слой инфраструктуры и данных)
*Этот слой отвечает за внешние коммуникации: сеть, базу данных и файловую систему.*

* **Модуль `MoexApiGateway` (Шлюз к Мосбирже):**
  * *Ответственность:* Прямые HTTP-запросы к API `iss.moex.com`. Умеет формировать корректные URL для акций, фондов, индексов и дивидендов. Обрабатывает сетевые ошибки и таймауты.
* **Модуль `MarketDatabase` (Рыночный кэш - Dexie.js):**
  * *Ответственность:* Прямой доступ к IndexedDB. Создание таблиц, запись и чтение цен, индексов и дивидендов. Содержит методы гранулярной очистки кэша (только акции, только индексы и т.д.).
* **Модуль `UserDataStorage` (Хранилище пользователя):**
  * *Ответственность:* Сохранение и чтение структуры портфелей, групп и глобальных настроек в изолированном локальном хранилище.
* **Модуль `FilePortabilityService` (Работа с файлами):**
  * *Ответственность:* Экспорт состояния приложения в JSON-файл и его импорт/валидация. Содержит адаптер для File System Access API (тихая перезапись файлов на ПК) с фоллбэком на классическое скачивание файлов через `Blob`.

---

### 3.3. APPLICATION LAYER (Слой оркестрации и состояния)
*Слой, который связывает интерфейс, базу данных и математическое ядро.*

* **Модуль `PortfolioStore` (Управление портфелями):**
  * *Ответственность:* Управление пользовательскими портфелями (CRUD). Вызывает `UserDataStorage` для сохранения и `TimelineEngine` для подготовки портфеля к расчету.
* **Модуль `MarketDataSyncService` (Оркестратор кэширования):**
  * *Ответственность:* Реализует паттерн Read-Through Cache. Когда приложению нужны цены для контрольной точки:
    1. Запрашивает данные из `MarketDatabase`.
    2. Если данных нет — вызывает `MoexApiGateway`.
    3. Сохраняет полученные данные в `MarketDatabase` и отдает их дальше.
* **Модуль `GroupLazyLoader` (Ленивая загрузка групп):**
  * *Ответственность:* Отслеживает активную группу портфелей. Блокирует фоновую загрузку цен для портфелей из неактивных групп до момента, пока пользователь не откроет эту группу.
* **Модуль `SettingsStore` (Глобальные настройки):**
  * *Ответственность:* Хранение ставки налога, списка переименований тикеров и вызов пересчета всех открытых портфелей при изменении настроек.

---

### 3.4. PRESENTATION LAYER (Слой пользовательского интерфейса)
*Отвечает только за отображение данных и реакцию на действия пользователя.*

* **Модуль `UI Shell & PWA`:**
  * Главный каркас приложения, плавающая шапка, переключатель тем, статус подключения к сети (Online/Offline), модальное окно установки PWA.
* **Модуль `DashboardView`:**
  * Отображение списка портфелей активной группы, переключение групп (табы), виджеты портфелей с цветовой индикацией Альфы (красный/желтый/зеленый).
* **Модуль `PortfolioDetailView`:**
  * Редактирование контрольных точек (Milestone Editor), добавление акций/фондов, визуальный контроль свободного кэша, кнопки ребалансировки.
* **Модуль `AnalyticsView`:**
  * Отрисовка графиков доходности (Recharts), переключение периодов (1М, 3М, YTD и т.д.), отображение Матрицы доходности по месяцам (с подсветкой неполных месяцев).
* **Модуль `SettingsAndCacheView`:**
  * Экран глобальных настроек, кнопки экспорта/импорта JSON, интерфейс гранулярной очистки кэша.

## 4. Сценарий взаимодействия модулей (Data Flow)

Для понимания гибости архитектуры проследим, что происходит, когда **пользователь добавляет новую контрольную точку в портфель**:

1. **Presentation (UI):** Пользователь выбирает дату и час в локальном времени, вводит тикер и нажатием кнопки "Сохранить" вызывает метод в `PortfolioStore`.
2. **Application (`PortfolioStore`):** 
   * Передает дату в `DateTimeStandardizer` для перевода в UTC.
   * Вызывает `UserDataStorage` для сохранения новой точки.
   * Запрашивает синхронизацию котировок у `MarketDataSyncService`.
3. **Application (`MarketDataSyncService`):**
   * Запрашивает у `TickerResolver` актуальный тикер для этой даты (например, меняет `T` на `TCSG`, если дата из прошлого).
   * Проверяет наличие цены в `MarketDatabase` (Dexie).
   * Если цены нет, берет цену через `MoexApiGateway` (если биржа закрыта, `CalendarAdjuster` смещает дату на ближайшую прошлую сессию).
   * Записывает свежую цену в `MarketDatabase`.
4. **Domain (`FinancialMath` & `TimelineEngine`):**
   * Получив все цены и историю дивидендов от сервисов, математическое ядро пересчитывает общую доходность портфеля, доходность LQDT для остатка кэша и вычисляет Альфу относительно MCFTR.
5. **Presentation (UI):**
   * `DashboardView` и `AnalyticsView` получают обновившиеся реактивные данные и перерисовывают карточку портфеля (обновляя цвет подцветки) и график доходности.

## 5. Преимущества для разработки и масштабирования

* **Тестируемость:** Математику ядра (`FinancialMath`, `TimelineEngine`) можно полностью покрыть Unit-тестами без запуска браузера или эмуляции DOM.
* **Замена источников данных:** Если завтра Мосбиржа изменит API, мы перепишем только модуль `MoexApiGateway`. Математика, хранилища и UI даже не заметят изменений.
* **Замена хранилищ:** Если захочется заменить Dexie.js на другую БД, мы заменим только класс в слое Infrastructure, соблюдая интерфейс `IMarketDatabase`.
* **Безопасный рефакторинг:** Разработчик, работающий над UI графиков (`AnalyticsView`), физически не может случайно сломать логику расчета сложного процента или налога на дивиденды.
